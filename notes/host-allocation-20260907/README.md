# Native allocation routing boundaries, 2026-09-07

The embedding port can route ordinary C++ new to an original Game arena. Aurora's persistent graphics resources must remain native even when a Game draw or constructor enters Aurora through GX. The public allocation.hpp header supplies a thread-local RoutingState, HostAllocationScope for native allocation owners, and ClientAllocationScope for actual synchronous client callbacks. Scope exit, including exception unwinding, restores both allocation and callback routing flags. The embedding allocator continues to own heap selection and lifetime.

The native guard sites are enumerated in surfaces.json. They cover FIFO growth/publication/drain and command decoding, direct GX copy/readback, texture caches/creation, bind-group/sampler caches, staging/recording/offscreen ownership, frame lifetime, depth snapshots and display-list optimization. Allocation-free GX setters retain their current fast path. Original Game execution is not globally switched to host allocation.

Synchronous GX draw-done, custom graphics/task callbacks, completion callbacks, virtual texture readers and frame-end callbacks restore the caller's saved routing only while invoking the client. Worker threads retain their own default host state; this header does not transfer a heap or invent lifetime retention across threads. Explicit client placement allocations and callback userdata remain owned by the embedding client.

OSLockMutex was audited for allocator recursion: the implementation uses static native synchronization primitives, intrusive SDK thread/mutex queues and an embedded thread_local OSThread initialized by field assignments. There is no first-use STL registry allocation on that path.

Initial validation: all twelve affected Aurora source units and the embedding JkrAllocationDomain unit passed LLVM23 syntax with their actual compilation database commands. The embedding integration tests and final source revision are recorded in validation.json once the coordinated run completes. This is a reusable allocation-boundary change; it does not establish complete game compatibility.


Final allocation revision validation: scheduler heap routing, the 96-texel DirectDraw test, and the extended actual-disc effect test all built and exited0. The scheduler verifies nested Host/Client scopes, explicit nested original domains and exception restoration. Each of two original effect scenes generated7 JPA particles and9 GPU draws, with2,391,153 changed RGBA bytes. Creating64 tagged depth snapshots under the actual Game scope left Game heap free size unchanged; a following original new still selected Game, and retained native snapshot metadata remained accessible after scene heap retirement.

Retained input storage was audited too. Debug-label APIs now take string_view and copy into host-owned strings inside the guard. end_frame takes a callback reference and copy-captures its std::function wrapper under host routing. TextureUpload and palette-conversion requests contain GPU/TextureRef handles rather than movable STL buffers. Opaque client callback pointees retain the existing caller lifetime contract. The debug string path also passed a separate syntax check with AURORA_GFX_DEBUG_GROUPS enabled.

Known independent issue: the preceding extended effect revision completed every assertion but aborted during final Metal shutdown in1 of6 processes; the next final allocation revision also exited0. The captured stack points to Dawn BufferBase::MapAsyncEvent::Complete. Inspection found discarded MapAsync futures and slot/buffer reset before callbacks are drained in native depth/frame/profiler teardown. That lifecycle fix is deliberately a subsequent checkpoint. These passes do not establish that the intermittent shutdown race is fixed.
